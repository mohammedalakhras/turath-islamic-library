# مكتبة التراث

منصة ثابتة (Static Site) مبنية بـ **Jekyll** لعرض الكتب التراثية والأثرية
مجاناً عبر **GitHub Pages**، مع تحسين كامل لمحركات البحث (SEO)، ووضع ليلي/نهاري،
وحفظ موضع القراءة، وتحميل PDF، ومشجرات Mermaid تفاعلية لكل كتاب وفصل.

## لماذا Jekyll؟

GitHub Pages يبني مواقع Jekyll تلقائياً بدون أي إعداد CI/CD — فقط ادفع (push)
الملفات وسيُبنى الموقع كصفحات HTML ثابتة فعلياً عند الطلب (ليست SPA)، وهذا
بالضبط ما تحتاجه الأرشفة: كل فصل من كل كتاب هو صفحة HTML مستقلة بعنوان ووصف
وبيانات Schema.org (`Book`/`Chapter`) خاصة به، وسيطمة (sitemap.xml) تلقائية
عبر `jekyll-sitemap`.

## التشغيل محلياً

```bash
bundle install
bundle exec jekyll serve
# افتح http://localhost:4000
```

## النشر على GitHub Pages

1. أنشئ مستودعاً باسم `username.github.io` (أو أي اسم آخر).
2. إن كان الاسم غير `username.github.io`، عدّل `baseurl` في `_config.yml`
   ليطابق اسم المستودع، مثل: `baseurl: "/heritage-library"`.
3. عدّل `url` في `_config.yml` إلى رابطك الفعلي.
4. من إعدادات المستودع (Settings → Pages)، اختر المصدر: `Deploy from a branch`
   → الفرع `main` → المجلد `/ (root)`.
5. ادفع (push) الملفات — سيُبنى الموقع تلقائياً خلال دقيقة أو دقيقتين.

## هيكل المشروع

```
heritage-library/
├── _config.yml           ← إعدادات الموقع والـ SEO
├── _data/books.yml       ← سجلّ كل الكتب (يظهر منه الكتاب في الصفحة الرئيسية)
├── _layouts/
│   ├── default.html      ← القالب العام (head, header, footer, scripts)
│   ├── book.html         ← قالب صفحة الكتاب الرئيسية
│   └── chapter.html      ← قالب صفحة الفصل
├── _includes/
│   ├── header.html / footer.html / sidebar.html
│   └── diagram.html      ← يغلّف أي مخطط Mermaid + التنبيه الإلزامي تحته
├── assets/
│   ├── css/style.css     ← نظام التصميم الكامل (الألوان/الخطوط/الوضع الليلي)
│   ├── js/main.js        ← الوضع الليلي، القائمة المنسدلة، حفظ موضع القراءة...
│   ├── pdf/              ← ضع هنا ملفات PDF لكل كتاب
│   └── img/covers/       ← ضع هنا أغلفة الكتب
├── books/
│   └── <book-slug>/
│       ├── index.md      ← صفحة الكتاب (ملخص + مخطط هيكلي عام)
│       └── chapter-XX.md ← كل فصل في ملف مستقل (نص الكتاب الحرفي + مخطط الفصل)
└── index.md              ← الصفحة الرئيسية (شبكة الكتب + الفلاتر)
```

## إضافة كتاب جديد (العملية الديناميكية)

لا حاجة لتعديل أي كود برمجي لإضافة كتاب جديد. فقط:

1. أنشئ مجلداً جديداً: `books/<book-slug>/` (بالحروف اللاتينية، بدون مسافات).
2. أضف `index.md` بنفس ترويسة (front matter) النموذج في `books/sample-book/index.md`:
   ```yaml
   ---
   layout: book
   permalink: /books/<book-slug>/
   title: "اسم الكتاب"
   book_slug: <book-slug>
   book_title: "اسم الكتاب"
   book_url: /books/<book-slug>/
   book:
     author: "..."
     era: "..."
     category: "..."
     pdf: /assets/pdf/<book-slug>.pdf
     summary: "..."
   ---
   ```
3. أضف ملف فصل لكل فصل: `chapter-01.md`, `chapter-02.md`, ... بنفس ترويسة نموذج
   `chapter-01.md`، مع `order` تصاعدي يحدد ترتيب الفصل في الفهرس والتنقّل.
4. ضع نص الكتاب الأصلي **حرفياً** داخل كل ملف فصل (بعد ترويسة الـ front matter)،
   دون أي تلخيص أو تعديل.
5. أضف مخطط Mermaid واحد أعلى `index.md` (هيكل الكتاب كاملاً) ومخططاً واحداً
   أعلى كل فصل (محتوى ذلك الفصل فقط) عبر `{% include diagram.html code="..." label="..." %}`.
6. ضع ملف الغلاف في `assets/img/covers/` وملف الـ PDF في `assets/pdf/`.
7. أضف سطراً جديداً في `_data/books.yml` بنفس الحقول، وسيظهر الكتاب تلقائياً
   في الصفحة الرئيسية وفلاتر التصنيف.

لا حاجة لأي بناء يدوي أو سكربت — Jekyll يكتشف كل ملف جديد في `books/` تلقائياً
عند البناء، والفهرس الجانبي والتنقّل بين الفصول يُبنيان تلقائياً من حقلي
`book_slug` و`order`.

## المبادئ المعمارية المهمة

- **لا SPA على الإطلاق**: كل صفحة (كتاب/فصل) هي HTML كامل مستقل، مفهرس بالكامل
  من Google فور النشر، تحتوي على نص الكتاب كاملاً في الـ DOM الأساسي.
- **النص لا يُمس**: القوالب لا تعدّل أو تلخّص أي نص؛ هي فقط "غلاف" حول النص.
- **المخططات توضيحية فقط**: كل مخطط Mermaid مرفق إلزامياً بنص تنبيه أنه ليس
  من تأليف الكاتب (مضمّن تلقائياً في `_includes/diagram.html`).
- **القائمة الجانبية Off-canvas** على الجوال لتفادي ازدحام الشاشة، مع عمود
  قراءة محدود العرض (`--measure`) لراحة العين.
- **حفظ موضع القراءة** عبر `localStorage` بمفتاح لكل كتاب على حدة
  (`heritage-progress:<slug>`)، يعمل بدون أي خادم أو قاعدة بيانات.
