# مكتبتي

أرشيف إلكتروني حر لأمهات الكتب التراثية والأثرية، بنصوصها الكاملة دون تحريف،
مبني كتطبيق **React (Next.js)** حقيقي، ومُصدَّر بالكامل إلى HTML ثابت ليُنشر
مجاناً على **GitHub Pages** مع تحسين SEO على أعلى مستوى ممكن.

## لماذا هذه البنية بالذات؟

كانت المحاولة السابقة (Jekyll) صحيحة من حيث المبدأ، لكنها انكسرت لأن روابط
وأصول الموقع لم تُضبط على اسم المستودع (`basePath`) يدوياً، فظهرت كل الصفحات
بدون أي تنسيق وبروابط 404. هذا الإصدار يحل المشكلة **جذرياً وليس يدوياً**:

- **Next.js مع `output: "export"`**: كل صفحة (الرئيسية، كل كتاب، كل فصل) تُصدَّر
  وقت البناء إلى ملف `index.html` **ثابت وكامل**، يحوي نص الكتاب الحرفي كاملاً
  داخل الـ HTML نفسه — تماماً كما تحتاجه الأرشفة الفورية من Google، دون أي
  اعتماد على تنفيذ JavaScript لإظهار النص. React يعمل فوق هذا الـ HTML
  لإضافة التفاعل فقط (الوضع الليلي، الفهرس المنسدل، شريط التقدّم).
- **`basePath` يُحسب تلقائياً** في `next.config.mjs` من اسم المستودع الذي
  توفره GitHub Actions أثناء البناء — فلا حاجة لكتابته يدوياً، ومن المستحيل
  تكرار نفس خطأ الروابط المكسورة التي واجهتها سابقاً.
- **`.nojekyll`** موجود في `public/` (ينتقل تلقائياً لجذر الموقع المنشور)
  ليمنع GitHub من معالجة مجلد `_next/` كأنه ملف Jekyll خاص وتجاهله.

## تفاصيل الـ SEO المطبّقة

- نص كامل وحقيقي لكل فصل داخل HTML الثابت (لا SPA فارغ ينتظر JavaScript).
- عنوان ووصف Meta مخصصان لكل صفحة (`generateMetadata`) + `rel=canonical`.
- بيانات Schema.org منظَّمة: `WebSite` في كل الموقع، `Book` في صفحة كل كتاب،
  `Chapter` في صفحة كل فصل — تساعد نتائج البحث الغنية (Rich Results).
- `sitemap.xml` و`robots.txt` يُولَّدان تلقائياً من محتوى الكتب الفعلي
  (`src/app/sitemap.ts` و`src/app/robots.ts`) — أي كتاب جديد يضاف تلقائياً
  للخريطة دون أي خطوة يدوية.
- كل فقرة من النص لها **رابط دائم (Deep Link)** خاص بها (`#p-1`, `#p-2`...)
  يظهر عند المرور عليها — مفيد لمشاركة اقتباس محدد ولأرشفة أدق.
- الخطوط (Amiri / Tajawal) تُحمَّل عبر `next/font/google` فتُضمَّن في الموقع
  وقت البناء (بدون أي طلب شبكة خارجي وقت التصفح)، ما يحسّن سرعة التحميل
  وبالتالي ترتيب الظهور في نتائج البحث (Core Web Vitals).
- HTML دلالي صحيح: `<article>`, `<nav aria-label>`, تسلسل عناوين h1→h2 سليم.

## المزايا المأخوذة من أفضل تطبيقات القراءة

بعد مراجعة أنماط التصميم المشتركة بين أفضل تطبيقات القراءة (Kindle, Apple
Books, Google Play Books، وتطبيقات EPUB المتخصصة)، تم تطبيق ما يلي تحديداً:

- **قائمة تحكم واحدة وفي نفس المكان دائماً** ("Aa" في الهيدر) بدل توزيع
  الإعدادات في عدة قوائم — أهم ما يميز أفضل التطبيقات تقييماً هو أن كل خيار
  "يصل إليه المستخدم خلال ثوانٍ" دون تعمّق في القوائم.
- **ثلاثة أوضاع قراءة لا وضعان**: نهاري / **سيبيا** (ورقي دافئ) / ليلي —
  السيبيا تحديداً هو الخيار المفضّل في جلسات القراءة الطويلة لأنه يريح العين
  أكثر من الأبيض الناصع دون قتامة الوضع الليلي الكامل.
- **تكبير/تصغير الخط بخطوات بسيطة** محفوظ بين الزيارات.
- **استئناف القراءة تلقائياً**: ليس فقط زر "تابع"، بل كل بطاقة كتاب في
  الصفحة الرئيسية تُظهر مباشرة أنك توقفت فيه سابقاً (نمط "Continue Reading"
  المعتمد في تطبيقات القراءة الكبرى).
- **تصميم هادئ ومقيّد (Restraint)**: عمود قراءة بعرض مريح، لا إغراق بالعناصر
  البصرية حول النص، وهو ما تجمع عليه مراجعات تجربة القراءة طويلة المدى.


## النشر على GitHub Pages

1. أنشئ مستودعاً (أي اسم، لا يشترط أن يكون `username.github.io`).
2. من إعدادات المستودع: **Settings → Pages → Source → GitHub Actions**
   (وليس "Deploy from a branch" — لأن المشروع يحتاج خطوة بناء `npm run build`).
3. افتح `.github/workflows/deploy.yml` وعدّل فقط القيمة التالية إلى نطاق
   حسابك الفعلي (بدون اسم المستودع في النهاية، يُضاف تلقائياً):
   ```yaml
   NEXT_PUBLIC_SITE_URL: "https://اسم-حسابك.github.io"
   ```
4. ادفع (push) إلى فرع `main` — سيبني الـ Action الموقع وينشره تلقائياً.
   تابع تقدّم النشر من تبويب **Actions** في المستودع.

## هيكل المشروع

```
maktabati/
├── content/books/<slug>/
│   ├── meta.json              ← بيانات الكتاب (عنوان، مؤلف، تصنيف، ملخص...)
│   └── chapters/*.json        ← كل فصل ملف JSON مستقل (العنوان + الأقسام + النص الحرفي)
├── src/
│   ├── lib/
│   │   ├── content.ts         ← قراءة المحتوى من القرص وقت البناء (خادم فقط)
│   │   ├── site.ts            ← دوال الروابط الآمنة للاستخدام من المتصفح أيضاً
│   │   └── types.ts
│   ├── components/            ← جميع مكوّنات الواجهة (معظمها عادي، والتفاعلي منها "use client")
│   └── app/
│       ├── layout.tsx         ← القالب العام، الخطوط، JSON-LD للموقع
│       ├── page.tsx           ← الصفحة الرئيسية
│       ├── sitemap.ts / robots.ts / manifest.ts
│       └── books/[slug]/
│           ├── layout.tsx     ← هيكل صفحة الكتاب (الفهرس الجانبي/المنسدل)
│           ├── page.tsx       ← صفحة الكتاب
│           └── [chapter]/page.tsx   ← صفحة الفصل (هذا هو مركز الثقل في الـ SEO)
├── public/                    ← الملفات الثابتة (PDF، الأغلفة، .nojekyll)
└── .github/workflows/deploy.yml
```

## إضافة كتاب جديد (العملية الديناميكية)

لا حاجة لأي تعديل برمجي. فقط:

1. أنشئ مجلداً: `content/books/<book-slug>/` (حروف لاتينية صغيرة بلا مسافات).
2. أضف `meta.json` بنفس حقول `content/books/sample-book/meta.json`.
3. أضف مجلد `chapters/` وملف JSON لكل فصل (`01.json`, `02.json`...) بنفس شكل
   النماذج الموجودة — كل ملف يحوي `slug` (رابط الفصل) و`order` (ترتيبه)
   و`sections` (مصفوفة أقسام، كل قسم له `heading` اختياري ومصفوفة
   `paragraphs` بنص الكتاب **الحرفي الكامل**، فقرة فقرة).
4. ضع الغلاف في `public/covers/<slug>.jpg` والـ PDF في `public/pdf/<slug>.pdf`.
5. ادفع (push) — سيكتشف Next.js الكتاب الجديد تلقائياً في البناء التالي
   ويضيفه للصفحة الرئيسية والفهرس وخريطة الموقع دون أي سطر كود إضافي.

## ملاحظة معمارية مهمة لأي تعديل مستقبلي

ملف `src/lib/content.ts` يستخدم `fs`/`path` (قراءة من القرص)، لذا **لا يجوز
استيراده من أي مكوّن يبدأ بـ `"use client"`** — سيفشل بناء حزمة المتصفح فوراً
(هذا بالضبط ما كشفه اختبار البناء أثناء إعداد هذا المشروع). أي دالة يحتاجها
مكوّن تفاعلي في المتصفح (مثل `withBase` لبناء رابط صورة) موجودة بدلاً من ذلك
في `src/lib/site.ts` الخالي من أي اعتماد على القرص.
